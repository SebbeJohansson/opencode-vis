# AGENTS.md

Context for AI agents working in this repository.

## Maintaining this file

This file is a living document. If you learn something while working here that a
future agent would need to know — a convention, a gotcha, a command, an
architectural constraint — add it. Keep entries short and factual, and delete
anything that has become wrong.

Rules for edits:

- One fact per entry, phrased so it is actionable without extra context.
- Only add things that are not already obvious from the code, the README, or git history.
- Do not add task-specific notes or changelog entries; this is not a log.

## Commands

- `yarn dev` runs Nuxt with the Nitro API on the same origin. `EXPERIMENTAL_CLAUDE=true OPENCODE_URL=http://localhost:4096 yarn dev` also enables the Claude routes.
- `yarn check` is lint + format check + typecheck + tests. Run it before calling work done.
- `yarn test:unit` (or `test:watch`) skips the `*.e2e.test.ts` files, which is the fast loop; `yarn test` runs everything.
- `yarn typecheck` runs `nuxt typecheck`. Never run bare `tsc` or `vue-tsc`: the project references live in `.nuxt/`, so they only exist after a prepare.
- `.nuxt/` is generated by `yarn dev`, `yarn typecheck` or `yarn nuxt prepare`. There is deliberately no `postinstall` hook, because `npx openui` would run it on a machine without Nuxt installed.
- `yarn generate` builds the static site (GitHub Pages needs `NUXT_APP_BASE_URL=/openui/`); `yarn build` builds the Nitro server that the npm package ships.
- Yarn only, via corepack. Never npm, pnpm or bun.

## Structure

- `app/` is the Nuxt `srcDir`. `pages/index.vue` is the only route.
- `server/` is Nitro: `api/config.get.ts` plus `api/claude/**`, with the Claude Code subprocess code in `server/utils/claude/`.
- `shared/` holds what both sides need: the `/api/config` response type and the `cc_` / `ccp_` id helpers.
- Components under `app/components/shell/` are the app shell. They hold markup only; behaviour lives in `app/composables/`.
- Feature composables are defined with `defineFeature()` from `useAppContext`. Each is created once per app context, inside the page's effect scope.

## Conventions

- Components may rely on Nuxt auto-imports. Files in `app/composables/`, `app/utils/`, `app/workers/` and `server/` use explicit imports.
- `app/utils/**` must not import Vue: the SharedWorker imports from there, and Nuxt's transforms do not run inside worker bundles.
- Tests are colocated `*.test.ts` and run in the `node` environment. A test that needs the Nuxt runtime opts in with `// @vitest-environment nuxt`.
- A `*.e2e.test.ts` boots a real build through `@nuxt/test-utils/e2e` and costs ~30s. Reserve it for route-level contracts; everything else is a unit test.
- Shared test helpers live in `test/nuxt/`. That is the only directory outside `app/` that Nuxt's app tsconfig typechecks, so a helper anywhere else is invisible to `yarn typecheck`.
- A feature composable needs a mounted `provideAppContext()` above it. Tests get one from `mountAppContext()` in `test/nuxt/app-context.ts` rather than calling the factory directly.

## Gotchas

- `ssr: false`. `window` and `localStorage` are safe, but module-level browser access still runs before mount, so keep it in a function or a plugin.
- `inject()` cannot see a `provide()` from the same component. `pages/index.vue` therefore passes the context it creates into `useAppBootstrap(ctx)`, and every feature-to-feature call passes `context` along.
- A feature must never reach for a template ref in a component it does not own. The shell components register their imperative APIs on `ctx.uiHooks` instead.
- The theme is applied before first paint by an inline script in `nuxt.config.ts`, not by a component.
- Editing anything under `server/` restarts the Nitro dev worker, which kills running Claude subprocesses and drops open SSE streams.
- h3 auto-imports its own `getSession`, so the Claude session accessors are named `getClaudeSession` / `getAllClaudeSessions`.
- `noUncheckedIndexedAccess` is off (`nuxt.config.ts`); the codebase predates it.
- `docs/demo.gif` is 6 MB. Do not re-encode or move it as a side effect of other work.
- `useMessages`, `useCredentials`, `useSettings` and `useIsMobile` keep their state at module level, so it survives a new app context. A test that mounts several contexts in one file has to reset them.
- `useSelectionRouting` fires `router.replace()` without awaiting it. A single `nextTick()` is not enough to see the new URL; wait until it stops changing.
